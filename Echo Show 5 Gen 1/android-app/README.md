# Spotify Desk Android display — first hardware prototype

This native Java Activity uses the existing paired HTTPS device gateway. It is deliberately not a HOME launcher or device owner yet. No HA server, remote administration, or Pi changes are required. Build with JDK 17, SDK 35, Build Tools 34.0.0, Gradle 8.9, AGP 8.7.3. Download Gradle from https://gradle.org/releases/ and verify the official SHA256.

From this directory on the development host, run `bash build-local.sh https://HOST:8443/ /path/to/verified-public-ca.crt` (replace HOST with the gateway's certificate hostname/IP). The script generates local ignored resources containing the address and CA; never commit generated resources, APK, debug keystore or private keys. The custom CA is scoped to the configured host, the rest of the network uses system roots, cleartext is disabled, main navigation stays on the configured HTTPS origin, TLS errors are cancelled. Android user-store CA installation is not required for this app. No JS/native bridge. CookieManager persists normal gateway session cookies. External HTTPS subresources such as artwork still use normal trust and server CSP.

Install `adb install -r app/build/outputs/apk/debug/app-debug.apk` then `adb shell am start -n com.spotifydesk.echo/.MainActivity`. Confirm the pairing page loads without TLS warnings before generating a one-time code through the Pi's existing gateway CLI. Never share a pairing code or use a TLS bypass. The app is fullscreen, keeps screen on while active, and swipe from edge then Back opens a native recovery menu. USB recovery: `adb shell am force-stop com.spotifydesk.echo` and `adb shell am start -a android.settings.SETTINGS`. No persistent launcher changes.

Test checklist: build, pairing, live Home/Spotify/Weather/Glucose/Calendar, reload and app restart cookie persistence, invalid TLS rejected, Wi-Fi outage and retry, Back/settings/exit, screen layout, Spotify art and actions. Do not set default HOME or enable lockdown until validated. Native volume routing, brightness, startup, update/signing lifecycle and speaker streaming remain future tasks. Debug APK only for local testing. This initial implementation has not been compiled or tested on the physical device yet.
