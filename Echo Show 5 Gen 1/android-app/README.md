# Spotify Desk Android display — first hardware prototype

This native Java Activity uses the existing paired HTTPS device gateway. It is now an optional HOME launcher via .HomeAlias, not a device owner. Default selection is explicit; installing the APK does not set the default. No HA server, remote administration, or Pi changes are required. Build with JDK 17, SDK 35, Build Tools 34.0.0, Gradle 8.9, AGP 8.7.3. Download Gradle from https://gradle.org/releases/ and verify the official SHA256.

From this directory on the development host, run `bash build-local.sh https://HOST:8443/ /path/to/verified-public-ca.crt` (replace HOST with the gateway's certificate hostname/IP). The script generates local ignored resources containing the address and CA; never commit generated resources, APK, debug keystore or private keys. The custom CA is scoped to the configured host, the rest of the network uses system roots, cleartext is disabled, main navigation stays on the configured HTTPS origin, TLS errors are cancelled. Android user-store CA installation is not required for this app. No JS/native bridge. CookieManager persists normal gateway session cookies. External HTTPS subresources such as artwork still use normal trust and server CSP.

Install `adb install -r app/build/outputs/apk/debug/app-debug.apk` then `adb shell am start -n com.spotifydesk.echo/.MainActivity`. Confirm the pairing page loads without TLS warnings before generating a one-time code through the Pi's existing gateway CLI. Never share a pairing code or use a TLS bypass. The app is fullscreen, keeps screen on while active, and swipe from edge then Back opens a native recovery menu. USB recovery: `adb shell am force-stop com.spotifydesk.echo` and `adb shell am start -a android.settings.SETTINGS`. The app does not change the default launcher itself.

Test checklist: build, pairing, live Home/Spotify/Weather/Glucose/Calendar, reload and app restart cookie persistence, invalid TLS rejected, Wi-Fi outage and retry, Back/settings/exit, screen layout, Spotify art and actions. Native volume routing, brightness, automatic network recovery, update/signing lifecycle and speaker streaming remain future tasks. Debug APK only for local testing.

Verify resolver before reboot; keep USB ADB and existing owner intact. No boot receiver, root, new permissions, lock task or TLS change. Source checks only; build and physical verification pending.

## Automatic connection recovery (0.3.0)

Second Echo reboot retained the HOME role and automatically opened Spotify Desk; first navigation failed before the dashboard appeared, with the native recovery panel visible. Exact network error not established. Transient main-frame WebView host lookup/connect/timeout/I/O/unknown failures and HTTP 500/502/503/504 now retry at 2, 4, 8, 15 then 30 seconds (30-second cap, only while resumed). Manual retry remains available; pause/destroy cancels pending callbacks. Successful page completion resets the delay. TLS callback still cancels and does not auto-retry; SSL handshake errors, blocked navigation and renderer crashes are not auto-retried. No change to trust, HOME configuration, cookie storage, permissions or Pi. Numeric error codes shown without private URLs. No background live API recovery is claimed.

Run standalone policy tests from android-app: `tmp=$(mktemp -d); javac -d "$tmp" app/src/main/java/com/spotifydesk/echo/RetryPolicy.java tests/RetryPolicyTest.java && java -cp "$tmp" com.spotifydesk.echo.RetryPolicyTest; rm -rf "$tmp"`. Then build and install in place, verify paired dashboard, cold reboot without interaction and Wi-Fi/Pi outage while loading. Verify Retry, settings and no TLS bypass. Do not clear app data or change launcher unless needed. APK and device tests pending.

## Local volume controls (0.4.0)

Physical GPIO volume keys confirmed through Android getevent; media stream has 0–15 steps on speaker, stock volume panel observed. Native foreground Activity handles only volume up/down, adjusts STREAM_MUSIC once on each down/repeat without FLAG_SHOW_UI, consumes key-up, displays actual stream level as a percentage in a top-centred two-second OSD across dashboard/recovery views. Uses normal MODIFY_AUDIO_SETTINGS permission; no runtime prompt, system overlay permission, JS bridge, firmware change or Pi changes. Other Android audio streams and hardware keys untouched; system behavior remains outside focused Activity. Fixed-volume devices or permission error delegate to Android. Remote Spotify volume and local Spotify playback not implemented here; label explicitly Echo Show volume. Android settings retains other sound sliders. Test single step, hold, bounds, mute, overlay timeout, no double adjustment or stock overlay, page navigation, recovery/reboot/pairing. Standalone VolumeScaleTest covers nine arithmetic cases; Android build/device behavior pending. Reinstall with existing signing key and generated TLS resources using adb install -r.
